## 1. 问题陈述

博客已有数学/物理文章与若干独立专题页，但没有一套从一阶逻辑走到独立性、再转入哲学逻辑与数学哲学的连续讲解。这个主题范围极大：若按教材目录铺开，会变成琐碎的百科；若只讲思想史，又会失去技术骨架。

目标读者处于大学低年级阶段：能理解变量、条件判断、函数与初等集合符号，有正常的抽象思维与批判性逻辑能力，但尚未建立形式系统的元理论视角。他们有三个典型痛点：

1. 容易把“符号串本身（语法）”与“符号所指的含义（语义/模型）”混为一谈；
2. 面对成堆公理时产生“人为武断感”，无法感知公理背后的工程动机与历史危机；
3. 容易被听起来顺畅、但底层机制错误的“庸俗生活化比喻”误导。

因此，本系列不是教材译本，也不是科普随笔，而是“硬核推演笔记 + 认知友好型自学手册”：形式精度不降，语言障碍要拆，比喻必须标明失效边界。

现有单页专题模式适合一本书式的大页面，但不适合 31 篇需要稳定单篇链接、增量发布、系列导航与前后篇依赖的连载。因此采用 MDX 连载 + 系列索引，而不是单文件 HTML。

## 3. 读者、教学目标与认知痛点

### 3.1 读者假设

- 能理解变量、条件判断、函数与初等集合符号。
- 读过一些初等证明，但不假设系统接触过形式证明、模型论或公理化集合论。
- 愿意读形式定义与证明，不满足于纯科普；遇到抽象处愿意停下来重读。
- 中文读者；英文术语首次出现时给原文。

### 3.2 教学目标

- 建立“语法 / 语义 / 证明 / 计算 / 集合论 / 哲学反思”六层地图，而不是背定理清单。
- 让读者能回答：这条公理删掉会怎样？这个定义在拦截什么？这个证明的机制是什么？
- 让读者区分“符号串”“满足关系”“证明”和“真理”，不把四者混为一谈。
- 让读者看到公理不是武断清单，而是对具体危机的工程回应。
- 让读者对核心比喻保持警惕：知道它在哪里有用，在哪里崩溃。
- 最终能读懂并评价关于独立性、新公理、逻辑多元论与数学基础的争论。

### 3.3 认知痛点与对应设计

| 痛点 | 表现 | 系列对策 |
|---|---|---|
| 语法/语义混淆 | 把公式真、可证、可满足当成同一件事 | 第一部先建语法，再建语义，再建证明；每次引入语义概念都显式对照语法对象 |
| 公理武断感 | “为什么偏偏是这几条？” | 第三部每条核心公理按“目的论与反事实困境”展开；外延公理作完整五维示范 |
| 庸俗比喻误导 | 用日常类比替代机制，外推出错误结论 | 三大底层公理 + `Metaphor` 组件强制写“破裂点”；附录维护隐喻账本 |

### 3.4 非目标

- 不是教材替代品，不追求覆盖所有定理与所有非经典逻辑。
- 不是逻辑学史或人物轶事集；历史只作第五部的骨架。
- 不包含 Lean/Coq 形式化。
- 不深入类型论、范畴逻辑、topos、HoTT、稳定性理论、优先级方法等专门分支。
- 不讨论超出逻辑语义需要的语言哲学。
- 不用“通俗但错误”的类比换取低门槛。

## 4. 教学法规范（融合附件）

### 4.1 三大底层公理

**公理 I：精度永不妥协。** 简化意味着消除语言障碍，不意味着降低形式精度。一个听起来言之成理、但描述错误底层机制的通俗解释，比未经解释的纯符号黑话更具毒性。若通俗解释与数学真实存在冲突，宁可引入精细的技术澄清，也不牺牲严密性。

**公理 II：概念零突兀产生。** 严禁在未从基础概念自底向上构建、且未作直观铺垫的情况下抛出后继概念。所有论述必须落在读者当前心智基线内；确需引入新术语，必须在引入当下给出“用直观语言展开的操作性定义”。

**公理 III：隐喻破裂必须显式声明。** 鼓励使用贴近计算思维与直观逻辑的隐喻，但任何隐喻在物理本质上都不等同于形式系统。每使用一个核心隐喻，必须明确指出该隐喻在何处崩溃，防止错误直觉外推。

### 4.2 五维展开模板

对任何形式公理、定义或关键元定理，按以下五维展开；每篇至少对**一个核心概念**做完整五维展开，其余定义用压缩版（目的论 + 形式规格 + 易错边界）。

1. **目的论与反事实困境（Teleology & Counterfactual Crisis）**：这条规则要解决什么漏洞、结构缺陷或表达力上限？如果缺失，会导致什么操作无法进行，或引发何种矛盾？
2. **形式化极简规格（Formal Specification）**：给出最标准、无歧义的形式化表达式；精确声明自由变量与论域范围。
3. **机制解构与自然语境对齐（Mechanism Deconstruction）**：逐字解构量词范围与连接词含义，用清晰的自然语言复述该规则的准入与拦截逻辑。
4. **隐喻映射与其失效边界（Metaphor & Breaking Point）**：引入技术直觉相近的结构隐喻；紧随其后说明形式数学与该隐喻脱钩的边界条件。
5. **易错边界与反直觉警示（Cognitive Pitfall & Boundary Warning）**：指出初学者最容易产生的概念滑坡；明确该规则“不等于什么”。

### 4.3 示范：外延公理

第 13 篇（ZFC）以附件示范为模板，完整展开外延公理：

- **目的论与反事实困境**：如果系统只有属于关系 $\in$ 而没有相等判定准则，我们无法确定两个包含相同元素的集合是否在形式上同一，也无法对集合进行替换。缺失它，数学将充满“名字不同、内容完全一致”的冗余幻影，函数外延性也会崩溃。
- **形式化极简规格**：$\forall x \forall y \, [\forall z (z \in x \leftrightarrow z \in y) \to x = y]$。
- **机制解构**：只要对全域中的任意对象 $z$，$z$ 属于 $x$ 与 $z$ 属于 $y$ 的真值始终同步，则 $x$ 与 $y$ 在符号系统内即可无条件相互替换。
- **隐喻与破裂边界**：类似于面向对象编程中重写 `equals()`——不比较内存地址，只按内部结构判等。破裂点：计算机中两个数据相同的对象仍占用不同物理地址，可通过指针区分；纯集合论中没有“内存地址”或“额外载体”，相同元素的集合在本体论上就是绝对同一的单个存在。
- **易错边界**：外延公理只定义“集合相等”，不定义“元素存在”；它不负责保障任何集合在逻辑宇宙中的真实存在性。

### 4.4 充分完备，拒绝膨胀

放弃僵化的字数硬性上限，采用“充分完备，拒绝膨胀”的软约束。

**终止条件**（三者同时满足即进入下一节，禁止横向展开）：

1. **形式闭环**：该概念的形式化定义已完整给出，无代数或逻辑未决项。
2. **动机成立**：读者能清晰回答“为什么不能删去这一部分”。
3. **陷阱排查**：已至少排查该概念最核心的一个初学认知混淆点。

**反膨胀不变量**：

- **跳过琐碎代数验算**：纯同义符号代换或直观良序归纳，给出关键代换关系后说明“其余按常规结构展开，此处略去”，不机械堆砌推演行数。
- **禁止跨阶段技术预支**：如果反例或引理需要后续章节的复杂工具，必须刹车，用一句话说明“技术后果将在后续深入”。
- **单篇聚焦唯一核心议题**：每篇只负责彻底打通一个系统演进阶段；禁止单篇覆盖从一阶演算到独立性证明的全部内容。

**与部预算的关系**：第 5 节的规划字数是工作量与节奏参考，不是硬性配额。若某篇在三条件满足后仍远低于规划，不强行填充；若明显超出且出现第二个核心议题，优先拆篇，不压缩必要内容。

### 4.5 对抗性自检协议

每章在作为最终稿前，必须通过以下四项检查（内部记录，不写进公开正文）：

- [ ] **机制纯洁性测试**：通俗解说是否存在“直观上顺理成章、但数学机制完全讲错”的致命硬伤？
- [ ] **隐喻破裂测试**：文中的核心比喻是否都指出了失效边界？
- [ ] **术语白名单测试**：是否存在读者心智模型中未曾出现、且当前章节未自底向上构建的高阶术语突然跳出？
- [ ] **冗余度测试**：是否存在无实质思想增量的证明步骤堆叠？

任一项失败，不得标记该章完成。

### 4.6 术语白名单与前置概念

- 每篇开头列“**前置概念**”：读者应已掌握的概念，并给出系列内对应章号。
- 每篇结尾列“**本篇新术语**”：本篇首次引入并已操作化定义的概念。
- 新术语只能出现在其构建章或更早；若确实需要提前使用，必须在当处给出临时操作化定义，并在构建章回链。
- 附录维护全系列术语表；每篇开头列前置概念，系列索引显示篇目、实际字数与完成状态。

### 4.7 隐喻账本

- 每个核心隐喻使用 `Metaphor` 组件，必须填写“映射”和“破裂点”两项；缺失破裂点时组件显示可见警告。
- 每篇最多保留 1–2 个核心隐喻；不为装饰使用比喻。
- 附录维护“隐喻—使用章—映射内容—失效边界”账本，便于跨篇检查是否外推过度。

### 4.8 习题、引用与核对

- 每章 3–5 道分层习题：概念检查、证明练习、延伸思考；另附 1–2 道开放性思考题。
- 关键题给提示（`<Hint>`，默认可折叠），不逐题给完整答案。
- 每部指定 1 本主教材 + 2 本辅助书；公开资源用于交叉核对；付费教材只进书目，不写未核对的页码或原话。
- 每篇末尾“本章核对来源”写清：核对了什么、用哪一源、哪些地方只给骨架。
- 不伪造定理编号、引文、页码或“作者原话”；主线定理至少两源交叉核对。

### 4.9 默认文风与排版

附件未覆盖的细项采用以下默认值；用户可随时覆盖。

- **人称与语气**：推导用“我们”，操作提示少量使用“你”；克制、清楚、不聊天化。
- **段落**：短到中等；一段一个意思；关键定义独立成段。
- **标题**：名词短语，明确承诺本章内容；不用点击诱饵式问句。
- **公式密度**：高，但每个符号首次出现即定义；长公式给阅读停顿，不堆砌。
- **例子**：数学内部例子优先；计算类比只在能标明破裂点时使用；历史案例集中在第五部。
- **哲学**：先陈述、再评估；保持论辩中立，不用嘲讽或人物八卦代替论证。
- **排版**：定理框、证明框、折叠提示、隐喻框、易错边界框；不做交互演示；静态图仅在必要处使用。
- **禁止**：错误类比、未建术语、无解释的“显然”、无思想增量的代数堆砌、伪造引用、科普腔鸡血句。

## 6. 站点实现

### 6.1 内容模型

`src/content.config.ts` 增加可选字段，保持现有文章兼容：

```ts
series: z.string().optional(),
seriesPart: z.number().int().min(0).optional(),
seriesOrder: z.number().int().min(0).optional(),
```

- `series` 存系列 ID（`forms-boundary`），不存中文长标题。
- `seriesPart` 取 0–6；0 表示导论，6 表示附录。
- `seriesOrder` 取 0–30；附录用 99。
- 现有 `title`、`pubDate`、`description`、`tags` 不变。

### 6.2 系列配置

新增 `src/data/series.ts`：

- `id`、`title`、`description`、`parts`（部次、标题、规划字数、简介）、`readingPaths`。
- 文章 frontmatter 只引用 `series` ID；中文标题与部次标题集中在配置中，避免重复。
- 系列索引与文章导航都从该配置读取部次与阅读路径。

### 6.3 路由与页面

- `/series/forms-boundary/`：系列索引，按部列出篇目、规划字数、完成状态、阅读路径。
- `src/pages/series/[id].astro`：用 `getStaticPaths` 从系列配置生成；未知 ID 返回 404。
- 文章页沿用 `src/pages/[...slug].astro`，在正文前后加入系列导航。
- 附录作为系列文章（`seriesOrder: 99`），复用文章排版与 KaTeX；不另造页面。

### 6.4 组件

- `SeriesBanner.astro`：文章顶部显示系列名、部次、篇序。
- `SeriesNav.astro`：底部系列内上一篇/下一篇；与普通文章前后篇分离。
- `Theorem.jsx`、`Definition.jsx`、`Proof.jsx`、`Exercise.jsx`、`Hint.jsx`：服务端渲染的轻量组件，无 `client:*` 指令。
- `Metaphor.jsx`：必须传 `mapping` 与 `breaking`；缺少 `breaking` 时显示可见警告，强制落实公理 III。
- `Theorem` 接受 `kind`、`number`、`title`；编号由作者按篇内手动维护。
- `Hint` 用原生 `<details>`，无 JavaScript 也能展开。
- 样式集中在现有全局样式或新增 `src/styles/series.css`，不引入外部字体或 CSS 框架。

### 6.5 导航与元数据

- 系列文章 `tags` 至少包含 `元数学`、`逻辑`；按部追加 `集合论`、`数学哲学` 等。
- 首页增加系列入口（单条卡片或链接），不新增大型专题区。
- `feed.json` 与 `source/[...slug].astro` 不改；验证系列文章正常出现/可查看源码。
- 文章 canonical、OG、description 沿用现有布局；系列索引页补齐 title/description。
- 内部链接使用 `import.meta.env.BASE_URL` 或项目现有链接工具，兼容 `/posts/` 基路径。

### 6.6 构建与验证

- 每批完成后运行 `pnpm build`，确保 schema、KaTeX、路由与链接无错误。
- 启动 `pnpm dev`，在浏览器检查样章：公式、定理框、隐喻框、目录、系列导航、移动端。
- 检查现有文章与 `source/` 页面无回归。
- 不引入客户端 JS 依赖；不新增外部资源请求。

## 7. 验收标准

### US-01 系列索引

作为读者，我可以从首页或直接 URL 打开 `/series/forms-boundary/`，看到五部结构、全部篇目、规划字数、阅读路径与完成状态。

验收：

- 31 篇正文与附录按部次、篇序正确分组。
- 未发布/未写篇目不显示为可点击链接，或明确标注“待写”。
- 阅读路径链接到正确篇目；移动端可读。

### US-02 文章内系列导航

作为读者，我在任意系列文章中能看到“第 X 部 · 第 Y 篇”，并跳到系列内上一篇/下一篇。

验收：

- 首篇不显示“上一篇”，末篇不显示“下一篇”；附录接在正文最后。
- 导航不混入按 `pubDate` 的普通前后篇。
- 链接在 `/posts/` 基路径下正确。

### US-03 单篇聚焦与五维展开

作为读者，我能在每篇看到一个明确的单一核心议题，并按五维模板理解核心概念。

验收：

- 每篇有唯一核心议题；不出现第二个完整展开的核心议题。
- 每篇至少一个核心概念走完五维；其余定义至少给目的论、形式规格、易错边界。
- 明确标注“留给后续”的内容不在本篇提前展开。

### US-04 隐喻与术语纪律

作为读者，我不会被错误类比或突兀术语误导。

验收：

- 每个核心隐喻有“破裂点”；`Metaphor` 组件缺少破裂点时构建/开发期可见警告。
- 每篇开头有前置概念，结尾有本篇新术语。
- 新术语未在前置概念或本篇构建中出现时，不得直接使用。

### US-05 内容质量与证明颗粒度

作为读者，我能按章读到定义、定理、证明、反思与习题；主线证明可检查，支线骨架有文献入口。

验收：

- 每篇有明确的动机、定义、定理/证明、习题、核对来源。
- 主线定理未被“证明略”带过；支线明确标注“证明骨架”并说明省略了什么。
- 哲学讨论只在部末或第五部出现，不打断技术主线。
- 术语与符号与附录一致。

### US-06 数学渲染与可访问性

作为读者，我能在桌面与移动端正常阅读公式、定理框、证明与提示。

验收：

- KaTeX 构建无报错；无未渲染的 `$...$` 或 `$$...$$`。
- 定理/定义/证明/隐喻框在亮暗主题下可读；不依赖颜色单独传达信息。
- 折叠提示可用键盘操作；打印/无 JS 时正文仍可读。
- 公式、表格不横向溢出；长公式可滚动。

### US-07 引用与核对

作为读者，我能看到每章的核对来源，且不会遇到伪造的页码、引文或定理编号。

验收：

- 每篇末尾有“本章核对来源”。
- 附录有完整参考文献、符号表、术语表、隐喻账本与引用规范。
- 未核对的内容不以确定语气引用；支线骨架明确标注。

### US-08 构建与回归

作为维护者，我能在不破坏现有站点的前提下构建整个系列。

验收：

- `pnpm build` 通过；无 schema 校验错误、无死链、无重复 slug。
- 现有文章、RSS、源码查看页、首页正常。
- 系列文章出现在 `feed.json`，源码查看页可访问。

### US-09 对抗性自检完成

作为作者，我在每章定稿前完成四项对抗性自检，并记录结果。

验收：

- 机制纯洁性、隐喻破裂、术语白名单、冗余度四项均通过。
- 任何一项失败时，章节不得标记完成。
- 样章与批量章节的检查记录可追溯。

## 9. 明确不做

- 类型论、范畴逻辑、topos、HoTT：只作延伸阅读，不设正文。
- 二阶逻辑、reverse math：只作节或专题，不展开完整理论。
- 高级模型论（稳定性、forking）、高级递归论（degrees、priority）：只提及。
- PA 以上的完整序数分析：只给骨架与结果。
- Lean/Coq 形式化：不做。
- 非经典逻辑的全景普查：只选代表系统，讲动机与代价。
- 语言哲学中超出逻辑语义的部分：只在必要处出现。
- 交互式演示、外部字体/图片/脚本：不做；只做 KaTeX 与静态图。
- 错误类比、未声明破裂点的隐喻、跨阶段技术预支、单篇大杂烩：禁止。
